# 模块文档更新

更新指定模块的架构文档，保持代码与文档同步。

## 目标文件

| 文档 | 路径                              | 更新条件 |
|------|---------------------------------|----------|
| 全局概览 | `.qoder/rules/base_overview.md` | 新增模块时更新模块索引 |
| 模块文档 | `docs/modules/{模块名}/module.md`          | 每次都更新 |

## 模块文档结构

> **原则**：模块文档是"行军地图"而非"兵器谱"——只记录模块骨架（API/类/流程/依赖），不逐字段罗列 DTO/VO/数据库列（AI 需要细节时直接读源码）。

```markdown
---
module: {模块名}
generated: {日期}
---

# {模块名} 模块文档

{一句话概述}

## 1. API 接口

| 方法 | 路径 | 说明 |
|------|------|------|

## 2. 核心类

| 类 | 职责 |
|------|------|

## 3. 数据模型

| 实体/表 | 说明 |
|------|------|

## 4. 关键流程

// 核心业务流程描述（精简，只记关键步骤和决策点）

## 5. 依赖

| 组件 | 用途 |
|------|------|

## 6. 配置

// application.yml 相关配置项

## 7. 注意事项（可选）

// 关键约束、约定、避坑要点
```

## 执行步骤

1. **确认模块名**：从用户输入提取模块名（如 mineru、doc、duediligence）
2. **搜索代码**：
   - Controller: `controller/` 目录
   - Service: `service/` 目录
   - Entity: `entity/` 目录（只需类名/表名，不展开字段）
   - SPI/Util: `spi/`、`util/` 目录
3. **分析结构**：提取 API 接口、核心类名及职责、实体/表名概览、依赖关系——**省略 DTO/VO 字段细节**
4. **更新模块文档**：创建或更新 `docs/modules/{模块}/module.md`
5. **检查全局概览**：如果是新增模块，更新 `base_overview.md` 的模块索引表

## 更新全局概览

当新增模块时，在 `base_overview.md` 的模块索引表中添加一行：

```markdown
| {模块名} | `{包路径}` | {简短说明} |
```

## 注意事项

- **文档应精简**：只记模块骨架，避免冗余描述。DTO/VO 字段细节、数据库列定义等，AI 需要时直接读源码即可
- **数据模型只记概览**：一张简表列出实体/表名 + 一句话说明，不展开字段
- API 表格按功能分组，按 order 排序
- 关键流程只记核心步骤和决策分支，省略实现细节（如临时文件清理、具体工具类名等）
- 坐标、格式等关键约定需明确记录
- 配置项使用 YAML 代码块展示
- 如有非显而易见的坑或约定，用"注意事项"节专门记录
