# 开发计划创建

根据用户输入的需求，在 `docs/02.开发计划/` 目录下创建结构化的开发计划文档。

## 文件命名

`{YYYYMMDD}_{功能名称}-development-plan.md`，如 `20260512_excel-to-html-tool-development-plan.md`

## 文档结构

> **原则**：计划文档聚焦"做什么、怎么做、产出什么"，技术方案中的 API 设计只记方法签名，不展开 VO 字段细节（与模块文档的"行军地图"原则一致）。

```markdown
# {功能名称}开发计划

## 一、需求概述
// 核心功能点列表，简明扼要

## 二、前置条件
// 依赖的模块/表/配置是否就绪？若未就绪，标注"需先完成"

## 三、技术方案
### 3.1 依赖分析
// 复用优先，列出所需依赖及状态（✅已有 / ❌待引入）

### 3.2 核心类设计
// 新增/修改的类及职责，目录树表达

### 3.3 关键流程
// 核心链路描述，只记关键步骤和决策点

### 3.4 API 设计
// 方法 + 路径 + 请求/响应类型，不展开 VO 字段

## 四、开发任务清单
// 分阶段任务表格，含序号、任务、优先级(P0/P1/P2)

## 五、注意事项
// 关键约束、边界情况、风险点

## 六、文件清单
// 文件路径 + 操作（新建/修改）表格

---
> 编写：{作者} | 日期：{日期}
```

## 执行步骤

1. 检查 `docs/02.开发计划/` 目录是否存在，若不存在则创建
2. 分析用户输入，提取功能名称和核心需求
3. 搜索现有类似实现，参考其代码结构（优先搜索 Controller/Service/Entity）
4. 查阅相关模块文档（`docs/modules/{模块}/module.md`），了解现有架构与约定
5. 设计技术方案（复用现有依赖优先，明确新增/修改的类）
6. 分解任务清单，按阶段组织，标注优先级
7. 创建文件 `docs/02.开发计划/{YYYYMMDD}_{功能名称}-development-plan.md`
